# Адаптивность календаря

Дата: 2026-10-11. Действующий контракт интерфейса: [DESIGN.md](../DESIGN.md).

## Какие размеры учитывать

Адаптация зависит от ширины **окна браузера в CSS-пикселях**, доступной высоты и безопасных областей экрана. Разрешение матрицы устройства и размер окна браузера различаются. Масштабирование, разделённый экран и панели браузера также меняют доступное пространство.

Перечислить все модели и настройки устройств невозможно. Поэтому макет использует непрерывные правила, а проверка сочетает характерные размеры устройств, промежуточные ширины и границы перестроения.

Размеры именованных устройств ниже взяты из [профилей Chromium DevTools](https://raw.githubusercontent.com/ChromeDevTools/devtools-frontend/main/front_end/models/emulation/EmulatedDevices.ts). Профиль iPad Mini обозначает именно пресет DevTools; размеры отдельных поколений устройства могут отличаться. Размеры ноутбуков здесь — проверяемые окна браузера.

## Что обнаружено

- Ограничение высоты внешнего попапа само по себе не обеспечивало видимость его содержимого. Например, при окне 844 × 390 иллюстрация Тогола с SVG высотой 120 px сжималась до контейнера высотой 40 px и обрезалась его `overflow: hidden`.
- У пяти попапов были разные правила высоты, прокрутки, внутренних отступов и кнопок закрытия.
- Подписи лунных дней зависели от отдельных диапазонов ширины и уменьшались до 8–9 px; `nowrap` вместе с ограничением ширины мог скрывать окончание слова.
- Меню года и месяца имели фиксированную максимальную высоту без учёта положения кнопки в окне. `scrollIntoView` выбранного пункта мог также прокручивать страницу.
- Значок события и счётчик дополнительных событий требовали больше ширины, чем узкая ячейка.

При базовой проверке 412 × 924 обычные информационные окна уже помещались в окно. Поэтому проверка дополнительно охватывает меньшую доступную высоту, смену ориентации, длинные описания и вложенные элементы; результат не основан только на размерах внешней рамки.

## Правила для элементов сайта

| Элемент | Правило адаптации |
| --- | --- |
| Главная шапка | Заголовок переносится; группа управления переходит на следующую строку при недостатке места. |
| Год, тема и язык | Кнопки сохраняют размер для касания; управляющая группа может переноситься. |
| Местоположение | Длинное название переносится; иконки сохраняют размер. |
| Годовая информация и легенда | Текст переносится; колонки легенды выбираются по доступной ширине. |
| Заголовки разделов | Текстовая часть может сжиматься и переноситься рядом с иконкой. |
| Годовой календарь | Все 12 месяцев сохраняются; до 760 px — одна колонка. Выше число колонок определяется доступной шириной контейнера, минимальная ширина карточки 426 px. |
| Шапка месяца и Рамазан | Метка периода переносится на отдельную строку при недостатке места. |
| Семидневные сетки | Семь `minmax(0, 1fr)` колонок; содержимое ячеек учитывает их фактическую ширину. |
| Лунный день | Полный текст, шрифт 11 px; узкая ячейка допускает перенос после дефиса. Высота ячейки оставляет место для обеих дат. |
| Несколько событий в дне | На узком экране значок и счётчик размещаются внутри ячейки. |
| Выбор года / лунного месяца | Меню открывается в сторону с большим доступным пространством, ограничивается видимым окном и safe areas; прокручивается только список. Названия и интервалы дат могут переноситься. |
| Тогол, Арсар, Мүчөл | Общая рамка `CalendarDialog`: видимый заголовок и закрытие, одна прокручиваемая область; иллюстрации и секции не сжимаются по высоте. |
| Примечательные даты | Та же рамка; длинные карточки событий прокручиваются полностью. До 600 px иконка стоит над текстом, оставляя описанию полную ширину. |
| Выбор местоположения | Прокручивается содержимое окна, включая поиск и города; элементы списка не сжимаются. Шрифт поля поиска 16 px. |
| Футер | До 820 px — одна колонка; длинные слова, адреса и названия переносятся. |
| Открытые попапы при изменении окна | Размеры обновляются по `visualViewport`, включая уменьшение доступной высоты. |
| Загрузка, ошибка, офлайн | Сохраняют существующее поведение и помещаются в доступную ширину. |

Попапы используют нативный `<dialog>` в верхнем слое браузера. Это устраняет зависимость от слоёв календаря и футера. Доступны Escape, удержание фокуса, возврат к открывшей кнопке и блокировка прокрутки фоновой страницы. Кнопка закрытия — 44 × 44 px.

## Повторяемая браузерная проверка

Требуются работающие API и Vite, Node.js 22+ и Chromium. Для существующих модульных проверок, импортирующих TypeScript напрямую, используется Node.js 24.

```bash
cd Front
npm run build
npm run check:responsive -- http://127.0.0.1:5177 /tmp/calendar-responsive.json
```

Короткий прогон:

```bash
QUICK=1 npm run check:responsive -- http://127.0.0.1:5177 /tmp/calendar-responsive-quick.json
```

Путь Chromium можно задать переменной `CHROMIUM`. Скрипт использует отдельный временный профиль и свободный порт отладки; после завершения закрывает браузер и удаляет свой профиль. Полный JSON-отчёт содержит измерения и нарушения; при нарушениях команда завершается с ненулевым кодом.

Проверки:

- Диапазон 320–1920 px с шагом 16 px и дополнительными ширинами возле брейкпоинтов и переходов сеток.
- Профили устройств и уменьшенной высоты; кыргызский и русский языки; светлая и тёмная темы.
- Горизонтальное переполнение страницы и элементов, текстовые границы подписей, пересечения дат и выход значков за ячейки.
- Все типы попапов, день с несколькими событиями, новолуние с пояснениями и конкретная дата 17.02.2026 с Мүчөл башы.
- Каждая вложенная строка текста доступна при прокрутке, её предки не обрезают текст, а прокручиваемая область целиком находится внутри рамки попапа. Проверка границы последнего контейнера не заменяет проверку самого текста.
- Иллюстрация сохраняет высоту; закрытие видно; фокус и прокрутка восстанавливаются.
- Колёсико достигает конца прокрутки. Отдельные свайпы через реальные `touchStart` / `touchMove` / `touchEnd` достигают конца пояснений Арсар и событий 17 февраля на Pixel, уменьшенном окне Pixel и iPad Pro 13 в обеих ориентациях.
- Открытые окна перестраиваются при изменении размера; все возвращённые API лунные месяцы проверяются на четырёх ширинах и обоих языках.

[Эмуляция DevTools](https://developer.chrome.com/docs/devtools/device-mode) проверяет поведение браузера при заданных параметрах. Она не заменяет проверку Safari или физических устройств. Отдельно остаётся проверка реальной экранной клавиатуры, панелей Safari и ОС.

## Первый полный прогон

Полный прогон: **836 сценариев, 0 нарушений** в Chrome/147.0.7727.116.

- 142 ширины × 4 комбинации языка/темы: 568 проверок страницы.
- 37 размеров окна × 4 комбинации: 148 сценариев с попапами и выпадающими списками.
- 16 изменений размера открытых попапов.
- 13 лунных месяцев × 4 ширины × 2 языка: 104 проверки.
- Отдельный свайп через touch-события на 412 × 500 прошёл.
- `npm run build` завершился успешно; шесть файлов существующих модульных проверок прошли.

Краткий машиночитаемый результат: [responsive-audit-summary.json](responsive-audit-summary.json). Полные измерения первого запуска: `/tmp/calendar-responsive-final.json`. Этот прогон проверял границу последнего контейнера; уточнённый контроль вложенных строк описан ниже.

В окне 844 × 390 иллюстрация Тогола теперь имеет контейнер 160 px для SVG 120 px. На уменьшенном окне Pixel 412 × 500 контейнер 124 px для SVG 96 px, а оставшийся текст доступен прокруткой.

Две прежние проверки, требовавшие буквально `scrollIntoView`, заменены проверками центрирования выбранного пункта внутри списка. Устаревшие ожидания имени в тесте футера синхронизированы с текстом, уже существовавшим в HEAD; содержимое футера не менялось.

## Повторное сообщение об обрезании на Pixel и iPad

Пользователь сообщил, что на Pixel 9/10 прокрутка событий 17.02.2026 заканчивается в середине пояснения Мүчөл башы, а пояснение Арсар ай тоже доступно не полностью. На iPad Pro 13 прокрутка выглядит отсутствующей. **Это сообщение пока не объяснено и не считается устранённым.**

На текущем сервере `http://127.0.0.1:5177` в отдельном профиле Chrome/147.0.7727.116 воспроизвести обрезание не удалось:

- Целевая диагностика: 20 случаев для двух языков, двух попапов и пяти размеров окна. Каждая вложенная строка доступна; колёсико и свайпы достигают конца. Размеры: 412 × 924, 412 × 500, 1032 × 1376, 1376 × 1032 и 1032 × 700. Измерения: `/tmp/calendar-dialog-touch.json`.
- Ещё четыре случая проверены с мобильным User-Agent и сенсорным режимом, включёнными до загрузки страницы; обрезание не повторилось. Измерения: `/tmp/calendar-dialog-mobile-load.json`.
- Уточнённый короткий прогон общего скрипта: **236 сценариев, 0 нарушений**. Он теперь включает iPad Pro 13 в обеих ориентациях, точную дату 17.02.2026, каждую вложенную строку и достижение конца прокрутки реальными событиями ввода. Измерения: `/tmp/calendar-responsive-text-lines.json`.

Для кыргызского текста при 412 × 924 область событий имеет высоту 685 px и содержимое 812 px; колёсико и свайп достигают `scrollTop = 127`. Арсар: 693/867 px и `scrollTop = 174`. На iPad 1032 × 1376 события требуют только 9 px прокрутки; кыргызский текст Арсар помещается целиком и не требует прокрутки.

Порты Vite 5173–5177 отдают текущий компонент `CalendarDialog` с `Cache-Control: no-cache`. Устаревший кеш или другая версия страницы остаются предположениями, а не установленной причиной. Для продолжения запрошены адрес страницы, версия браузера и скриншот после прокрутки до упора. CSS и компонент попапа при этой повторной диагностике не менялись.
